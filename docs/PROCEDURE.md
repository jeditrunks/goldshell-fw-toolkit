# Procedure — building a root-SSH KD Box II firmware from stock

This is the exact recipe that produced `firmware/kdbox2-custom-2.2.7.cpb`. It starts from a
**stock Goldshell package** and ends with a signed, flashable `.cpb` that any KD Box II
verifying against `fw_cmpt.verify.pem` will accept.

Everything is scripted: `tools/build.py` does steps 2–7 and `tools/flash.sh` does step 9.
The prose here exists so you can repair the scripts when the next firmware revision moves
things around.

---

## 0. Prerequisites

```
squashfs-tools     (mksquashfs, unsquashfs)
openssl            (1.1 or 3.x is fine)
python3            (3.8+, stdlib only)
curl, xxd          (flash only)
```

Plus the vendor key pair, which lives in this repo:

| file | purpose |
|---|---|
| `keys/fw_cmpt.pem` | Goldshell OTA **private** key, passphrase `<vendor-passphrase>` |
| `keys/fw_cmpt.verify.pem` | its public half — what the device verifies with |
| `keys/id_rsa.pub` | the SSH key baked into the image |

`fw_cmpt.pem` is extracted from `/root/settings/` inside any stock rootfs. It is not
generated by us and cannot be replaced — its public half is compiled into what the device
trusts.

---

## 1. Get a stock package

Download the matching stock `.cpb` for the unit (e.g. `firmware-Goldshell-KDBoxⅡ-2.2.7.cpb`
from <https://github.com/goldshellminer/firmware>).

**Keep it.** It is your rollback. Store it next to the output, not in `/tmp`.

Record its size and hash — you will compare against it at the end:

```sh
sha256sum firmware-*.cpb
```

---

## 2. Understand the container before touching it

`tools/build.py --inspect stock.cpb` (or do it by hand):

```
+0x000   512-byte header: "firmware-MCB_<MCB_VERSION>.tgz" NUL-padded
+0x200   gzip member 0  → tar { firmware.ius (16,630,272), firmware.ius.sig (512) }
         ...padded to the next 1024-byte boundary (filler is high-entropy, not zeros)
+...     gzip member 1  → tar { firmware.ius (44,570,112), firmware.ius.sig (512) }
+...     trailer, file padded to 1024
```

Rules that matter:

- **Both members must be present.** A package with only member 0 makes `minerd` crash and
  respawn instead of updating — you get `Minerd start !!!` in the syslog and nothing else.
- Member 1 is the **hashrate-board** image. Do not rebuild it; copy it **byte-identical**
  from the stock package, trailer included.
- Member 0's gzip, once decompressed, must be **exactly 16,640,000 bytes** of tar for 2.2.7
  (16,630,272 + 512 + tar overhead). The `upgrade` binary is picky about the inner image size,
  not the outer compression ratio.
- Padding is 1024-byte alignment, not block padding. Get the alignment wrong and the scan in
  `FUN_000127f8` never finds the package.

Decompress member 0 and keep `firmware.ius` + `firmware.ius.sig`.

---

## 3. Carve the rootfs out of `firmware.ius`

Layout (2.2.7, confirmed):

```
0x00        "+ius"
0x04        format version = 2
0x10        version string, ASCII "2.2.7"
0x18        unknown word (0x089def12)
0x1c        image count = 6
0x30        16-byte entries: [tag, index, 0x40000, size]  (index 4 / size 0xc52000 = our rootfs)
0x389E00    rootfs squashfs  (image 12,918,784 max in-region; region to EOF = 12,919,808)
```

The table's semantics were never fully resolved, which is why we never rewrite it. We patch
the squashfs **in place**: same region length, zero-fill the tail, leave offsets and table
entries untouched. After patching, every differing byte must fall inside the region — the
build script asserts this.

Extract:

```sh
unsquashfs -d root stock-rootfs.sqfs
```

---

## 4. Modify the rootfs (minimum viable root)

| change | why |
|---|---|
| `root/.ssh/authorized_keys` ← `keys/id_rsa.pub`, `chmod 700 .ssh` / `600 authorized_keys` | key-based root login |
| `etc/init.d/S50sshd`: `stop()` body replaced with an `echo` | `minerd` calls `S50sshd stop` at boot, which is `killall sshd`. This single call *is* the "SSH disabled" mechanism. |
| `etc/sshd_config`: append `PermitRootLogin yes`, `PasswordAuthentication no`, `UseDNS no` | the stock config ships the root-login lines commented out |
| `etc/kdbox-custom-fw` marker | lets you prove from a shell which image is running |

`UseDNS no` is not cosmetic — without it sshd stalls on reverse lookup and logins take
~10 s.

### Fitting the region

The stock squashfs is **12,917,584 bytes** of a **12,918,784** budget — 1.2 KB of headroom,
and mksquashfs output is not byte-stable, so any edit overflows.

The build drops `root/yottamc/fonts/materialdesignicons-webfont.64d4cf64.eot` (~1 MB, the
IE-only format of a font whose woff2/ttf siblings stay). That frees ~470 KB. If a future
revision needs more, the candidates in size order are `boot/uImage` (2.6 MB),
`usr/bin/xvgminer` (2.3 MB), the `.ttf` (1.0 MB).

**Never** drop anything `minerd`, `xminerd` or `kdaminer` links against.

### Repack with the stock parameters

```sh
mksquashfs root rootfs.sqfs \
    -comp gzip -b 131072 -no-xattrs -noappend -all-root -nopad -Xcompression-level 9
```

- `-b 131072` — stock block size; mismatch changes mount behaviour on the 3.10 kernel.
- `-all-root` — **mandatory.** Without it the image is built with the host uid (3000 here)
  and sudo-less daemons can't read their own config.
- `-nopad` — otherwise 4 KB of padding is appended and you blow the region.
- Then assert `size <= 12918784`.

## 5. Patch the image in place

```python
d = bytearray(open('firmware.ius','rb').read())
OFF, REGION = 0x389E00, len(d) - 0x389E00        # 3,710,464 / 12,919,808
assert len(sqfs) <= 12918784
d[OFF:OFF+REGION] = b'\x00' * REGION                # zero first, never partial-overwrite
d[OFF:OFF+len(sqfs)] = sqfs
```

File length stays 16,630,272. If it changes, you are no longer producing a 2.2.7 image and
the second container member is no longer a match.

---

## 6. Sign it

```sh
openssl dgst -sha256 \
    -sign keys/fw_cmpt.pem -passin pass:$GOLDSHELL_KEY_PASS \
    -out firmware.ius.sig firmware.ius

openssl dgst -sha256 -verify keys/fw_cmpt.verify.pem \
    -signature firmware.ius.sig firmware.ius      # → Verified OK
```

Scheme: RSA-4096 PKCS#1 v1.5 / SHA-256 over the whole `firmware.ius`. The device's verify
path (`FUN_0000cd68`) runs exactly the second command. **Signature only** — no CRC, no
length checks, no table validation. That is why in-place patching is safe.

If step 6 doesn't print `Verified OK`, stop. A bad signature is the only rejection that
leaves the box perfectly healthy, and you'll just waste 4 minutes finding out.

---

## 7. Rewrap the `.cpb`

```python
hdr      = stock[:512]                    # byte-identical, carries firmware-MCB_<ver>.tgz
m1_tail  = stock[16446464:]               # member 1 + trailer, byte-identical
raw      = tar(('firmware.ius', ius), ('firmware.ius.sig', sig))   # GNU format, mtime fixed
m0       = gzip.compress(raw, 9)
pad      = (-(512 + len(m0))) % 1024
out      = hdr + m0 + b'\x00'*pad + m1_tail
```

Use **GNU tar format** and give both members a fixed `mtime`, otherwise every build differs.
`tools/build.py` is deterministic (`gzip.compress(..., mtime=0)`), so two runs produce
identical bytes.

Verification checklist before flashing (the script enforces all of these):

1. header is byte-identical to stock;
2. member 0 decompresses to exactly 16,640,000 bytes;
3. that tar contains `firmware.ius` (16,625,280... 16,630,272) and `firmware.ius.sig` (512);
4. extracted `.ius` has the same length as stock, and **all** differing bytes are inside
   `[0x389E00, 0x389E00+REGION)`;
5. signature verifies against `fw_cmpt.verify.pem`;
6. the squashfs inside the packaged `.ius` mounts (`unsquashfs -s`) and lists
   `root/.ssh/authorized_keys` and `etc/kdbox-custom-fw`;
7. file is 1024-byte aligned after member 0.

## 8. Flash

```sh
./tools/flash.sh <miner-ip> firmware/kdbox2-custom-2.2.7.cpb firmware-MCB_V6_3_5.tgz
```

To do the same thing by hand in a browser (System → unlock → Update → pick the `.cpb`),
see [WEBGUI.md](WEBGUI.md). Same endpoint, same verification, same ~3.5 minutes — the GUI is
just a friendlier client for step 3 below.

What it does:

1. `GET /user/login?username=<u>&password=<hex>&cipher=true` — password is AES-128-CBC
   encrypted with the static key `!!!!!!!!!!!!!!!!`, zero IV, zero padding, hex-encoded.
   Wrong password returns **HTTP 500**, not 401.
2. Takes `JWT Token` from the JSON and sends `Authorization: Bearer <jwt>`.
3. `POST /mcb/uploadimage`, multipart field `file`, **filename must be
   `firmware-<MCB_VERSION>.tgz`** — `FUN_000127f8` deletes anything in the download
   directory that doesn't match that pattern.
4. Then the update thread: verify → `/root/update_arm.sh` → kills userspace, `pivot_root`s
   into a tmpfs copy, runs `upgrade <package>`, reboots.

Timing on real hardware: `POST → 200` in ~7 s, services die immediately, box unreachable for
~2.5 min, back after **~3.5 min total** from the POST.

If the POST returns 200 and the box stays up with `Minerd start !!!` in the log, the
container was rejected without being written — no harm done, but nothing was installed.

## 9. Verify on the device

```sh
ssh -i ~/.ssh/kdbox_rsa \
    -o IdentitiesOnly=yes -o PubkeyAcceptedAlgorithms=+ssh-rsa \
    root@<miner-ip> 'id; cat /etc/kdbox-custom-fw; uptime'
```

Expect `uid=0(root) gid=0(root) groups=0(root),10(wheel)` and the marker.

Login gotcha, verified on `.198` (2026-10-28): a bare `ssh root@<ip>` fails with
`Permission denied (publickey,…)` — the default key set is rejected. You need
`-i` to name the key, `IdentitiesOnly=yes` so no earlier agent key eats the
offer, and `PubkeyAcceptedAlgorithms=+ssh-rsa` because newer clients dropped
ssh-rsa user-key signatures by default (`PubkeyAcceptedKeyTypes` is the
deprecated alias of the same option, used in older copies of this doc). The
host key needs no flag: the box's 6.4p1 sshd offers an ECDSA host key, so the
handshake is fine with defaults.

Then confirm mining survived with the cgminer API on port 4028:

```sh
python3 -c "import socket,json; s=socket.create_connection(('<ip>',4028),5); \
s.sendall(b'{\"command\":\"devs\"}\n'); d=b''; \
[d:=d+s.recv(65536) for _ in iter(int,1)] if False else None"
```

or just open the web UI. Expect `Status: Alive`, the hashrate and accepted shares.

## 10. Rollback

Flashing replaces the **rootfs (`spiblock1`) only**. SPL and kernel (`spiblock0`) are never
written by this path, so a bad rootfs still boots far enough to accept a new upload in most
cases.

Rollback = upload the stock `.cpb` through the same endpoint with the same filename. Keep
the stock package on disk before you start.

If the box never comes back on the network:

- LAN LED / link up but no HTTP → rootfs mounted badly; needs the J2 console.
- No link at all → bootloader or hardware issue; not caused by this procedure.

J2 is 3.3 V, 115200 8N1, and sits behind a MOSFET level shifter — it needs a push-pull
driver (ESP32 etc.), not a bare USB-TTL.

## 11. Adapting to a different unit or firmware version

Check the target first:

```sh
curl -s http://<ip>/mcb/status
# {"hardware":"B2.CS.SA","model":"Goldshell-KDBoxⅡ","mcbversion":"MCB_V6_3_5","firmware":"2.2.7"}
```

Three things are version-bound and all three must come from that unit's stock package:

- the 512-byte `.cpb` header (`firmware-<mcbversion>.tgz`);
- the inner `firmware.ius` (version string at `0x10`, table at `0x30`, **rootfs offset**
  at `0x389E00` — re-derive it, don't assume);
- container member 1.

So: **always rebuild from that unit's own stock `.cpb`, never rename ours.** Renaming only
changes the filename, not the image, and a mismatched inner image is the one way to make a
box that needs a serial cable.

The SSHD patch and the key are version-independent — `etc/init.d/S50sshd` and
`root/.ssh/authorized_keys` look the same across these 2.x builds.

## 12. Gotchas worth remembering

- `.cpb` with one member → `minerd` crashes and respawns instead of updating.
- `mksquashfs` without `-all-root` → image owned by uid 3000, daemons can't read config.
- `mksquashfs` without `-nopad`/`-no-xattrs` → image larger than the region.
- Non-1024-aligned member → package scan never finds it, update silently doesn't run.
- Password is AES-encrypted on the wire but the key is a literal in the web bundle:
  the login is obfuscated, not protected.
- The web UI's "wrong password" is a 500. Don't chase a server bug.
- `/mcb/restart` and `/mcb/wifisetting` are unauthenticated in this firmware — the PSK is
  readable by anyone on the LAN. Rotate it; this procedure doesn't fix that.
- Pre-flight facts confirmed on `.198` running our image (2026-10-28): the updater
  CLI **is** on the box, at `/usr/bin/upgrade` (its name contains no "updat" — easy to
  miss), and the runner script the minerd thread calls is `/root/update_arm.sh`, not in
  /usr/bin or /usr/sbin. The upload staging path is `/dev/shm/minerd/download/`, live and
  empty between updates. None of these change the procedure: flash.sh needs no box-side
  CLI and no shell — it uploads through the web API and the daemon does the rest.
